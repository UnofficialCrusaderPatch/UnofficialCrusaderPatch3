# Framework 3.0.8

- Add the option to run multiple game instances and use separate logs per instance.
- Show the active setup digest on the main menu.
- Ask before running with security disabled from the command line.
- Fix ZIP directory alias listing and safe logging of AOB scan and extraction results.
- Opening a directory entry or a file that cannot be extracted from an extension zip fails with a message instead of giving an empty file.
- Faster startup: AOB scans without a range search the game executable's image instead of memory up to 0x7FFFFFFF, a cached AOB address is checked by comparing its bytes, and an entry that no longer matches is searched again on its own instead of clearing the whole cache.
- `core.matchesAOB(target, address)` tells whether an AOB matches at an address.
- `core.AOBScanUnique(target)` returns the address of an AOB that occurs exactly once in the game executable's code, or nil and "not found", "found more than once" or "not searched completely". Each call scans the code; the result is not cached. `--ucp-allow-multiple-instances` uses it.
- `core.sha256File(path)` returns a file's SHA-256, computed natively in chunks. The path is resolved exactly like `io.open`'s, including path aliases.
- RPS 1.6.0: `core.scanForAOB` keeps to its range, `max` included, and does not read past the end of a memory region.
- `data.version.getGameLanguage()` reads the language name from the game folder's cr.tex when the game's language index is 0 (English or a name the game does not know): "Русский" is "russian", other names are returned in lowercase. It returns "spanish" in lowercase.
- The userdata interface accepts `_` in paths and adds `rename(from, to)`, which replaces an existing file in one step.
